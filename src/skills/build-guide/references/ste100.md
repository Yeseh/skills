# ASD-STE100 Simplified Technical English, at about 80%

ASD-STE100 is a controlled language for technical documentation. It makes text easy to read for people whose first language is not English, and it removes ambiguity. The official specification is at https://www.asd-ste100.org/. It contains a dictionary of approved words and 53 writing rules. This file gives the rules that have the most effect, and the relaxations for this guide.

"About 80%" means: apply the strict rules to all instructions, milestones, and traps. In concept explanations, you can relax some rules (see the end of this file). The checker script (`scripts/ste_check.py`) gives a score. The target is 80% or more.

## Strict rules (always)

### Words
- Use one word for one meaning, and one meaning for one word. When you select a term for a thing (for example "supervisor"), use only that term in the full guide. Do not change to "parent", "host process", or "manager" for variety.
- Use simple, approved words. Replace these:

| Do not use | Use |
| --- | --- |
| utilize, leverage, employ | use |
| facilitate, enable | let, make possible, help |
| in order to | to |
| prior to | before |
| subsequent to | after |
| commence, initiate | start |
| terminate (for a person's action) | stop |
| ensure | make sure |
| obtain, acquire, retrieve | get |
| sufficient | enough |
| approximately | about |
| additional | more |
| numerous | many |
| require | need |
| perform | do |
| attempt | try |
| verify | make sure, check |
| determine | find, decide |
| indicate | show |
| robust, seamless, powerful | (delete, or say what it does) |

- Do not use phrasal verbs (verb + particle with a new meaning). Use a single verb:

| Do not use | Use |
| --- | --- |
| set up | configure, make, prepare |
| figure out | find |
| find out | find, learn |
| come up with | make, find |
| look into | examine |
| carry out | do |
| point out | show |
| go through | read, examine |
| get rid of | remove |
| run into | get, have |
| fill in | write, complete |
| pick up | continue, start again |

- Do not use slang or jargon that is not a technical name.
- Do not use contractions. Write "do not", "it is", "you will".

### Noun clusters
- Do not use more than three nouns together. "session cgroup memory limit" is four nouns. Write "the memory limit of the session cgroup".

### Verbs
- Use only these verb forms: infinitive, imperative, simple present, simple past, simple future, and past participle as an adjective.
- Do not use progressive forms ("is running" → "runs").
- Do not use "-ing" words as nouns or adjectives when another word is possible ("the setting up of mounts" → "the mount configuration"; "the remaining steps" → "the other steps"). Technical names that end in "-ing" are permitted (for example "string", "logging", "networking", "padding").
- Use the active voice. "The filter is installed by the child" → "The child installs the filter".

### Sentences
- Procedural sentences (instructions, steps, milestones): 20 words maximum.
- Descriptive sentences (explanations): 25 words maximum.
- Write one instruction in one sentence. Two instructions in one sentence are permitted only when the user does them at the same time.
- Put a condition before the instruction: "If the map write fails, stop the child."
- Do not remove articles ("the", "a") to make sentences shorter.
- Use vertical lists for three or more items or steps.

### Instructions
- Use the imperative: "Mark the mounts private." Not "You should mark the mounts private" and not "The mounts should be marked private".
- Start a warning with a clear command, then give the risk: "Install the filter last. If you install it earlier, it can block the setup syscalls."

### Paragraphs
- Write one topic in one paragraph.
- Write six sentences or fewer in one paragraph.
- Put the most important information first.

## Relaxed rules (concept explanations only)

These relaxations make the guide pleasant to read. Use them only in "Why" callouts and "Concepts" sections.

- You can use a common word that is not in the STE dictionary when it is clearer than the approved word (for example "hide", "leak", "bound", "blast radius").
- You can write a descriptive sentence of up to 30 words if you cannot split it without loss of meaning. Do this rarely.
- You can use the passive voice when the actor is unknown or not important ("The page is mapped at fork time").
- You can use a short analogy to explain a concept.

## Examples

| Not STE | STE |
| --- | --- |
| You'll want to make sure that you're setting up the uid map before the child starts doing any mounts. | Write the uid map before the child mounts a filesystem. |
| The filter should be installed last, since it can end up blocking syscalls that are needed by the setup code. | Install the filter last. If you install it earlier, it can block syscalls that the setup code needs. |
| Leverage cgroups to enable robust resource limiting. | Use cgroups to limit memory, CPU time, and the number of processes. |
| Figure out where your delegated subtree is. | Find your delegated cgroup subtree. |
